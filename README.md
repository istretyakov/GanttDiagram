# Диаграммы Ганта по задачам Jira

Веб-приложение: загружает задачи эпиков из **Jira Server / Data Center**, раскладывает их на ресурсной
диаграмме Ганта (строки — участники), позволяет планировать мышью, отправляет плановые сроки обратно в Jira,
показывает нагрузку исполнителя по всем проектам и экспортирует диаграмму в **PlantUML** и **Mermaid**.
Подробный план и решения — в [PLAN.md](PLAN.md).

## Быстрый старт (разработка)

Нужны .NET SDK 10, Node.js 22.12+, Docker.

```bash
docker compose up -d postgres
```

```bash
dotnet run --project backend/src/GanttDiagram.Api --launch-profile http
```

```bash
npm --prefix frontend install
```

```bash
npm --prefix frontend run dev
```

Откройте http://127.0.0.1:5173. API — http://localhost:5080 (OpenAPI: `/openapi/v1.json`), миграции
применяются при старте. Без Jira можно нажать **«Демо-данные»** на странице проектов (только в Development).

Всё приложение в Docker: `docker compose --profile app up -d --build` → http://localhost:8080.

## Как пользоваться

1. **Подключения Jira** → «Подключение»: адрес Jira и Personal Access Token → «Подключиться». В адрес можно
   вставить ссылку на любую задачу или доску (`https://jira.company.local/browse/PRJ-12`) — адрес сервера
   и проект определятся сами. После подключения выбираются **один или несколько проектов** Jira — эпики
   и пользователи берутся из всех выбранных (в «Добавить эпики» можно сузить поиск до одного). Поля
   «ожидаемое начало» (в Jira нет стандартного поля: `Start date`, `Target start` или своё) и «ожидаемое
   окончание» подставляются автоматически. **Иерархия задач** — связи Jira, по которым задачи вкладываются
   друг в друга в списках («родитель <связь> дочерняя»); по умолчанию предлагаются связи вида «включает»
   и «Tested by». Дочерние задачи по этим связям (например, тесты) загружаются вместе с эпиком, даже если
   они вне эпика. Поля дат подставляются сами, название — по серверу и проекту. Сохранять до проверки не нужно.
2. **Проекты** → создать проект → «Добавить эпики»: поиск эпиков в Jira, импорт задач.
   **«Копировать»** (на карточке и странице проекта, или «На основе проекта» при создании) делает новый
   проект с теми же эпиками, задачами и участниками — по выбору. Задачи Jira общие: плановые даты и
   исполнитель задачи одинаковы во всех проектах, куда она входит.
3. **Диаграмма**: «+ Участник» добавляет строку из синхронизированных пользователей Jira; задачи из правой
   панели перетаскиваются на строку участника; полосу можно двигать целиком, тянуть за края, переносить
   между участниками или обратно в панель («снять с плана»). Ctrl+Z / Ctrl+Shift+Z — отмена и повтор,
   Ctrl+S — **«Сохранить»** (все правки разом, в локальную БД).
4. **Нагрузка**: задачи человека по всем проектам, гистограмма часов по дням, перегрузка — красным.
5. **Экспорт** на диаграмме и на экране нагрузки: PlantUML (`.puml`) или Mermaid (`.mmd`), копирование,
   скачивание, предпросмотр Mermaid в браузере. Для предпросмотра PlantUML укажите внутренний
   PlantUML-сервер компании (публичный `plantuml.com` не используется).

6. **Отправить в Jira** (страница проекта, кнопка «В Jira» на диаграмме): предпросмотр «Jira → план» по
   каждой задаче, выбор задач, по желанию — переназначение исполнителя, подтверждение. В Jira пишутся
   только **сохранённые** плановые даты (`PUT /rest/api/2/issue/{key}`, исполнитель —
   `PUT …/assignee`), не больше 4 запросов параллельно. Перед записью задача перечитывается: если её
   изменили в Jira после последней синхронизации, она не записывается (конфликт), а снимок Jira
   обновляется. Результат — по каждой задаче: записано / конфликт / ошибка, неотправленные можно повторить.
   Токену нужны права Edit Issues (и Assign Issues), а поля дат должны быть на экране редактирования задачи.

Пересинхронизация обновляет снимок Jira и **не затирает** локальные правки; расхождение плана с Jira
помечается значком `≠`, задачу можно «Сбросить к Jira» или отправить план в Jira.

## Настройки API (`appsettings.json` / переменные окружения)

| Ключ | Назначение |
|---|---|
| `ConnectionStrings:Default` | PostgreSQL |
| `DataProtection:KeysPath` | папка ключей шифрования токенов Jira (потеря ключей → токены нужно ввести заново) |
| `Jira:Proxy` | корпоративный прокси; иначе системный / `HTTPS_PROXY` |
| `JIRA_SSL_VERIFY` | `false` (или `0`, `no`, `off`) — не проверять SSL-сертификат Jira (внутренний или самоподписанный). Задан в профиле запуска `launchSettings.json` и в `docker-compose.yml`; при старте API пишет предупреждение в лог. То же самое — `Jira:AllowInvalidCertificates=true` |
| `Database:MigrateOnStartup` | применять миграции при старте (по умолчанию `true`) |
| `Cors:Origins` | разрешённые origin'ы, если frontend на другом адресе |

Сертификат внутреннего ЦС для Docker-образа кладётся в `backend/certs/*.crt`.

## Тесты

```bash
dotnet test backend
```

Unit, snapshot-тесты экспорта (Verify, эталоны в `backend/tests/GanttDiagram.Tests/Export/Snapshots`)
и интеграционные (Testcontainers PostgreSQL + WireMock.Net вместо Jira) — нужен запущенный Docker.

```bash
npm --prefix frontend test
```

Vitest: даты, дорожки, нагрузка, черновик правок (undo/redo), палитра, разбор эталонов Mermaid парсером `mermaid`.

```bash
npm --prefix frontend run e2e
```

Playwright (API замокан): перетаскивание и растягивание полос, перенос между участниками и из списка,
Esc, undo/redo, сохранение. Если браузер Playwright не установлен, можно взять системный:
`PW_CHANNEL=msedge` или `PW_CHANNEL=chrome`.

## Структура

```
backend/
  src/GanttDiagram.Domain          сущности, расчёт рабочих дней
  src/GanttDiagram.Application     сервисы (импорт, диаграмма, нагрузка, экспорт), DTO
  src/GanttDiagram.Infrastructure  EF Core + миграции, клиент Jira Server, Data Protection, демо-данные
  src/GanttDiagram.Api             Minimal API, ProblemDetails, OpenAPI
  tests/GanttDiagram.Tests
frontend/
  src/api            типы из OpenAPI (npm run gen:api) и хуки TanStack Query
  src/features/gantt шкала, полосы (Pointer Events), панель задач (dnd-kit), черновик (Zustand)
  src/features/export, src/features/workload
  src/pages          Подключения, Проекты, Проект, Диаграмма, Нагрузка
  e2e/               Playwright
```
